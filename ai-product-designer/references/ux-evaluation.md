# UX Evaluation and Audit Framework

## Purpose

Provide a systematic approach for evaluating digital product experiences, identifying usability issues, and recommending improvements.

## 1. Define audit scope

Before conducting an audit, identify:

- Product and platform
- Target users
- Business objective
- Screens or workflows
- Primary user tasks
- Available evidence
- Technical and business constraints

Do not evaluate a screen without understanding its purpose in the broader journey.

## 2. Evaluation dimensions

Evaluate the experience across these dimensions:

| Dimension | Evaluation focus |
|---|---|
| Usability | Can users complete tasks easily? |
| Navigation | Can users find what they need? |
| Information hierarchy | Is important information prioritised? |
| Consistency | Are patterns and interactions predictable? |
| Feedback | Does the system communicate outcomes? |
| Error prevention | Are mistakes prevented where possible? |
| Error recovery | Can users recover from failures? |
| Accessibility | Can users with different abilities use it? |
| Trust | Are important actions and information clear? |
| Efficiency | Are unnecessary steps removed? |

## 3. Heuristic evaluation

Use established usability principles as evaluation lenses:

1. Visibility of system status
2. Match between the system and the real world
3. User control and freedom
4. Consistency and standards
5. Error prevention
6. Recognition rather than recall
7. Flexibility and efficiency
8. Minimal and focused design
9. Clear error diagnosis and recovery
10. Help and documentation

Treat these as evaluation principles, not a substitute for usability testing.

## 4. Accessibility considerations

Review:

- Text readability
- Colour contrast
- Focus visibility
- Keyboard accessibility
- Touch target size
- Screen reader compatibility
- Form labels
- Error identification
- Alternative text
- Meaningful status feedback

Use applicable accessibility standards when the evaluation requires formal compliance.

## 5. Classify findings by severity

| Severity | Definition |
|---|---|
| Critical | Blocks task completion or creates serious risk |
| High | Causes significant friction or frequent failure |
| Medium | Creates noticeable usability difficulty |
| Low | Minor inconsistency or improvement opportunity |

Explain the rationale behind each severity classification.

## 6. Audit finding template

For each issue, document:

**Issue title:** Short description.

**Location:** Screen or interaction.

**Observation:** What is happening?

**Evidence:** Screenshot, test observation, or supplied information.

**User impact:** How does this affect the user?

**Severity:** Critical, High, Medium, or Low.

**Recommendation:** What should change?

**Expected outcome:** What improvement is anticipated?

Clearly label recommendations that have not yet been validated.

## 7. Prioritise improvements

Consider:

- Severity
- User impact
- Frequency
- Business impact
- Implementation effort
- Technical dependencies

Address blockers and high-impact issues before cosmetic refinements.

## 8. Recommended deliverables

- Audit scope
- Evaluation methodology
- Findings table
- Annotated observations
- Severity classification
- Recommended improvements
- Prioritised action plan
- Validation approach

## Quality checklist

- Is the evaluation grounded in the actual experience?
- Are findings specific?
- Is there supporting evidence?
- Are recommendations actionable?
- Are accessibility concerns considered?
- Are edge cases included?
- Are priorities justified?
- Is validation needed?

## Guiding principle

A UX audit should identify problems that affect user outcomes, not simply list visual preferences.
